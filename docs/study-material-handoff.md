# 从课表到学习资料交接
# From Timetable to Study-Material Handoff

日历协调和资料下载是两个不同动作。先确认课次日期、类型与取消/补课状态，再把来源材料映射到该课次；不根据文件刚被下载就判断“今天要上这节课”。

Calendar coordination and file download are separate actions. Confirm the class date, type and cancellation/rescheduling status, then map source files to that class; a newly downloaded file does not imply a class is happening today.

## 预习窗口
## Preparation Window

三自然日模式使用今天及未来两天，不顺延成三个有课日。提前下载的资料在进入窗口时重新复核；课表更新后只重新核对受影响课次。

A three-calendar-day window means today plus the next two days, not the next three teaching days. Revisit early downloads when their classes enter the window; recheck affected mappings after a timetable update.

## 分开记录四件事
## Track Four Different Events

1. 下载完成：原文件已保存，来源与版本明确。
2. 交接送达：指定处理者已收到这个批次；未知响应不自动重发。
3. 成果制作：输出覆盖约定来源，图、表、题目和答案完成核对。
4. 归档确认：从准确目标目录独立读回成果，保留原文件身份和已有链接。

English:

1. Downloaded: the original file is saved with its source and version.
2. Delivered: the intended processor received this batch; an uncertain response does not trigger blind resending.
3. Produced: output covers the agreed sources, with figures, tables, questions and answers checked.
4. Archived: read the output back independently from the exact target folder, retaining stable file identity and links.

发送状态不能代替成果完成。用户暂停的批次保持暂停；没有可操作变化时不发送重复通知。

Delivery is not completion. User-paused batches stay paused; do not send repeated notices when nothing actionable changed.
